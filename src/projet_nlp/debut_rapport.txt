1) Essai de différents modèles de transformers sur Huggingface pour trouver le plus efficaces :

J'ai pris tous les messages et j'ai gardé ceux annoté, j'ai equilibré le nombre de BULLISH/BEARISH pour l'entrainement et le test.
Les messages ont été modifié pour supprimer toute mention de leur ticker afin de ne pas apprendre sur la popularité des symboles mais bien
sur le sens des phrases.
Les tickers considérés sont TSLA, AAPL, AMD, NVDA, GOOGL, META : je les ai choisi car les utilisateurs qui parlent de l'un vont parler des autres
et cela est intéressant pour pouvoir mieux généraliser lorsque l'on veut créer un embedding utlisateur pour rajouter du contexte à la prédiction.

Je l'ai donc choisi pour poursuivre mon étude.

Certains tweets sont plus facilement catégorisable : notamenent les tweets plus long.
Précision en fonction de la taille des messages à partir d'un entrainement sur 1500000 messages (vraimen 1500000 cette fois). Test sur 15000 tweets :

J'ai découvert que le fait de passer un liste de token bornée permet un gain de perfomances énorme et un usage moindre de la mémoire.
J'ai donc adapté le process pour entrainer par tranche : d'abord les tweets de moins de 32 puis entre 32 et 64 (moins nombreux) etc.
Le gain de performance est spectaculaire.
J'ai trouvé aussi que pour interpréter un embedding généré, le mieux etait de récupérer un layer du modèle plutot que de faire un réseau complétement
connecté.
Une tête simple est généralement plus performante.
Il ne faut surtout pas entrainer le transformer sur plus de deux époques sinon il apprend par coeur : on voit la loss diminuer mais la performance 
n'augmente pas (voir diminue). La solution est d'utiliser beaucoup de messages (ce qui est assez lent à traiter).

2) Ajout de contexte pour améliorer la prédiction

J'utilise 1500000 messages pour l'entrainnement (l'ajout des embeddings, prend beaucoup de RAM)

2 idées : 
- Certains messages sont neutre et viennent en réponse a d'autres ; certains sont ambigu : la première idée consiste à prendre en compte les précédents
messages pour voir si on peut clarifier ces twwets : chaque tweet produit un embedding et on créé une colonne previous qui est une moyenne pondérée des 
précédent tweet avec un mécanisme d'attention sommaire : current_mean := (previous_embedding + current_mean) / 2
l'embedding ainsi obtenu est ramené sur un latent de dimension 2 pour généralisation
- Certains utilisateurs ont une façon bien à eux de s'exprimer et il est intéressant donner un descriptif de l'utilisateur : on peut le représenter comme
l'embedding ainsi obtenu est ramené sur un latent de dimension 2 pour généralisation

Les performances sont (test sur 60000 tweets) :

modèle utilisé                                     perfomances
roberta + simple tete de classification          : 83.14%
ajout du user embedding                          : 88.24%
ajout du previous embedding                      : 86.19%
ajout du previous embedding et du user embedding : 88.72%

Dans le cas previous embedding + user embedding, on remarque un gain significatif pour les petits messages (test sur 15000 tweets) : 

                                                   T<=32   32<T<=64   64<T<=128   128<T<=256
roberta + simple tete de classification          : 82.5%     88.0%      91.9%        91.1%
ajout du user embedding                          : 88.9%     91.4%      89.4%        91.1%
ajout du previous embedding                      : 86.6%     86.7%      88.6%        90.2%
ajout du previous embedding et du user embedding : 89.1%     89.6%      88.7%        90.3%

Sur les tweets long (qui sont beaucoup moins nombreux), on note une légère baisse de performances avec l'ajout du contexte surtout celui du previous
 embedding. Mais la performance globale s'améliore car les tweets majoritaires font moins de 32 tokens. Si on prennait les perfs max pour chaque modèle,
 on voit qu'on atteindrait les 90% au global ...

Conclusion : on peut donc avoir une très bonne prévision des tweets en prennant en compte la personnalité de l'utilisateur et ses précédent tweets, et
ce, même avec des tweets ambigus. 

Points qui reste en suspend :

- Il serait intéressant de fournir le nombre de tokens au modèle pour que celui-ci apprenne à faire d'avantage confiance à l'embedding de l'utilisateur
lorsque celui-ci a suffisament de tokens (et donc moins utiliser les infos du contexte) : Avec un peu plus de temps sur ce projet, cela aurait été la 
prochaine étape.
- On pourrait essayer d'améliorer la prise en compte des messages précédents : régler mieux l'attention
- Gérer les tweets qui sont des réponses, rajouter le tweet initial en contexte
- Il serait intéressant de voir si un user embedding reste crédible longtemps si on ne fait de mise à jour 
- Les hyper paramètres du réseau que j'ai créé doivent pouvoir être optimisés 
- Il arrive parfois qu'un modèle "collapse" en début d'entrainement (même le modèle le plus simple avec 1 tête de classification) :
Dans ce cas la, je relance et le shuffle fait l'affaire : je pense que pour stabiliser l'apprentissage il serait peut être intéressant de le
 nourrir au début avec des tweets qui sont certainnement non ambigu.
